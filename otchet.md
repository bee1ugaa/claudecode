# Отчёт: «Диагностика сети средствами Python», вариант 1

**Исходные данные:** HOST = `google.com`, NETWORK = `192.168.1.0/24`,
отделы: Продажи — 50, Бухгалтерия — 25, Серверная — 10, Линк — 2.

Код программы: [`diag.py`](diag.py). Запуск: `python3 diag.py` (в Windows: `python diag.py`).

> Скриншоты нужно сделать при запуске на своём компьютере с доступом в Интернет.
> IP-адрес google.com и время соединения у вас будут свои.

## Задание 1. check_dns

Ожидаемый вывод:

```
[DNS ] google.com -> 142.250.xxx.xxx
[DNS ] ОШИБКА: не удалось определить IP-адрес для qwerty12345.invalid ([Errno 11001] getaddrinfo failed)
```

(текст ошибки в скобках зависит от ОС; в Linux — `[Errno -2] Name or service not known`).

**Вопрос: каким протоколом и на каком уровне стека выполняется запрос?**
Запрос выполняется протоколом **DNS** — это **прикладной уровень** стека TCP/IP.
Сам DNS-запрос обычно передаётся по UDP, порт 53 (транспортный уровень).

## Задание 2. check_tcp

Ожидаемый вывод:

```
[DNS ] google.com -> 142.250.xxx.xxx
[TCP ] 142.250.xxx.xxx:443 открыт, соединение за 25 мс
[TCP ] 127.0.0.1:65000 ОТКАЗ: узел отвечает, но порт закрыт
```

Опыт `check_tcp("10.255.255.1", 80, timeout=2)` — в зависимости от сети будет
`ТАЙМАУТ: нет ответа за 2 с` или `ОШИБКА: ... Network is unreachable`.
Это отличается от ОТКАЗА тем, что до узла 10.255.255.1 пакеты вообще не доходят
(или ответ не возвращается), а при ОТКАЗЕ узел живой и сам отвечает «порт закрыт».

**Вопрос: чем с точки зрения диагностики отличаются ОТКАЗ и ТАЙМАУТ?**

- **ОТКАЗ** (ConnectionRefusedError) — узел доступен по сети и ответил пакетом
  TCP RST: «на этом порту никто не слушает». Сеть исправна, проблема в службе
  на узле (не запущена, слушает другой порт).
- **ТАЙМАУТ** (socket.timeout) — ответа нет вообще: узел выключен, нет пути до
  него или пакеты молча отбрасывает файрвол. Искать проблему нужно в сети
  (маршрутизация, межсетевой экран).

## Задание 3. check_http

Ожидаемый вывод:

```
[HTTP] google.com:80 -> HTTP/1.1 301 Moved Permanently
[HTTP] localhost:65000 ОШИБКА: [WinError 10061] ...   (в Linux: [Errno 111] Connection refused)
```

Статус 301 — нормальный ответ: сервер перенаправляет на другой адрес.

Дополнительно, `print(data.split("\r\n")[:6])` — обычно в ответе google.com видны
заголовки (проверьте у себя, набор может отличаться):

- `Location: http://www.google.com/` — куда перенаправляет сервер;
- `Content-Type: text/html; charset=UTF-8` — тип содержимого;
- `Server: gws` — программа веб-сервера Google.

**Вопрос: зачем нужен заголовок Host? Как связаны HTTP и TCP?**
На одном IP-адресе может работать много сайтов, и по одному IP сервер не знает,
какой сайт запрашивают. Заголовок `Host` сообщает имя нужного сайта.
HTTP — протокол прикладного уровня, он работает **поверх TCP**: сначала
устанавливается TCP-соединение с портом 80 (или 443), затем по нему передаются
текстовый HTTP-запрос и ответ. Без TCP-соединения HTTP-запрос отправить нельзя.

## Задание 4. diagnose

| Запуск | На каком шаге остановилась программа | Вывод программы | Какой утилитой можно проверить то же |
|---|---|---|---|
| `diagnose(HOST)` | Не остановилась, пройдены все 3 шага (DNS, TCP, HTTP) | ВЫВОД: все проверенные уровни работают | `nslookup google.com`, `telnet google.com 443` (или `Test-NetConnection google.com -Port 443`), `curl -I http://google.com` |
| `diagnose("qwerty12345.invalid")` | Шаг 1 — DNS | ВЫВОД: проблема на прикладном уровне (DNS) | `nslookup qwerty12345.invalid` |
| `diagnose("localhost", tcp_port=65000)` | Шаг 2 — TCP-соединение (DNS прошёл: localhost → 127.0.0.1) | ВЫВОД: проблема на транспортном/межсетевом уровне (TCP-соединение) | `telnet localhost 65000`, `Test-NetConnection localhost -Port 65000`, `netstat -an` |

## Задание 5. vlsm

Вывод программы (получен при запуске):

```
Отдел         Треб. Сеть              Маска           Первый IP     Последний IP  Broadcast
Продажи       50    192.168.1.0/26    255.255.255.192 192.168.1.1   192.168.1.62  192.168.1.63
Бухгалтерия   25    192.168.1.64/27   255.255.255.224 192.168.1.65  192.168.1.94  192.168.1.95
Серверная     10    192.168.1.96/28   255.255.255.240 192.168.1.97  192.168.1.110 192.168.1.111
Линк          2     192.168.1.112/30  255.255.255.252 192.168.1.113 192.168.1.114 192.168.1.115
Самопроверка VLSM: ВСЁ ВЕРНО
```

Ручной расчёт (h — бит под узлы, 2^h − 2 ≥ N):

| Отдел | N | h | 2^h − 2 | Префикс |
|---|---|---|---|---|
| Продажи | 50 | 6 | 62 | /26 |
| Бухгалтерия | 25 | 5 | 30 | /27 |
| Серверная | 10 | 4 | 14 | /28 |
| Линк | 2 | 2 | 2 | /30 |

Занято адресов 192.168.1.0 – 192.168.1.115, свободно 192.168.1.116 – 192.168.1.255.

**Опыт с 62, 63 и 64 узлами (отдел «Продажи»)** — результат программы:

```
Продажи = 62: 192.168.1.0/26, узлов в блоке 62
Продажи = 63: 192.168.1.0/25, узлов в блоке 126
Продажи = 64: 192.168.1.0/25, узлов в блоке 126
```

- 62 узла: h = 6, 2^6 − 2 = 62 ≥ 62 — хватает, префикс **/26**.
- 63 узла: 2^6 − 2 = 62 < 63 — не хватает, нужен h = 7: 2^7 − 2 = 126, префикс **/25**.
- 64 узла: так же h = 7, префикс **/25**.

Вывод: блок /26 вмещает максимум 62 узла. Если нужен хотя бы один адрес сверх 62,
блок удваивается до /25 (126 узлов).

**Вопрос: почему отделы выделяются от большего к меньшему?**
Размер блока — степень двойки, и блок должен начинаться с адреса, кратного своему
размеру. Если начинать с больших блоков, каждый следующий (меньший) блок
автоматически начинается с «ровного» адреса, и блоки ложатся подряд без пропусков
и наложений. Если начать с маленького, большой блок пришлось бы сдвигать до
кратного адреса и адреса между ними пропали бы.

**Вопрос: почему в формуле вычитаются два адреса?**
В каждой подсети первый адрес — адрес самой сети, последний — широковещательный
(broadcast). Их нельзя назначить узлам, поэтому из 2^h адресов узлам достаётся 2^h − 2.

## Задание 6. check_ping

Ожидаемый вывод:

```
[PING] 127.0.0.1 отвечает
[PING] google.com отвечает          (или: НЕ отвечает (код 1))
=== Диагностика google.com ===
...
ВЫВОД: все проверенные уровни работают
```

Если `ping google.com` не проходит, а `diagnose` показывает, что сайт доступен,
значит в сети (на файрволе колледжа или провайдера) закрыт протокол **ICMP**,
а TCP-порты 80/443 открыты. ping и TCP-проверка используют разные протоколы,
поэтому «нет ping» не означает «узел недоступен».

Если появляется «Operation not permitted» — для отправки ICMP-пакетов ping нужны
«сырые» сокеты (raw socket), которые в Linux доступны только root или программе
с правом CAP_NET_RAW (или разрешённой группе в `net.ipv4.ping_group_range`).
Обычному пользователю система это запретила.

> В программе учтено, что в Windows у ping другие ключи (`-n` вместо `-c`,
> `-w` в миллисекундах вместо `-W`), поэтому check_ping работает и в Windows, и в Linux.

## Контрольные вопросы

**1. Что делает socket.gethostbyname и какому протоколу и уровню стека соответствует?**
Отправляет DNS-запрос и возвращает IPv4-адрес по имени узла. Протокол DNS,
прикладной уровень (передаётся обычно по UDP, порт 53). Если имя не найдено —
исключение `socket.gaierror`.

**2. Чем ConnectionRefusedError отличается от socket.timeout?**
ConnectionRefusedError — узел ответил отказом (TCP RST): он доступен, но порт закрыт,
служба не запущена. socket.timeout — ответа нет совсем за отведённое время: узел
недоступен, нет маршрута или пакеты отбрасывает файрвол. Первое указывает на проблему
со службой на узле, второе — на проблему в сети.

**3. Почему HTTP-запрос — это просто текст? Зачем нужен заголовок Host?**
HTTP/1.1 — текстовый протокол: запрос состоит из строк вида `GET / HTTP/1.1`,
`Host: ...`, оканчивающихся `\r\n`, и пустой строки в конце. Поэтому его можно
сформировать обычной строкой и отправить в TCP-сокет. Host нужен, потому что на одном
IP-адресе может быть много сайтов, и сервер по Host определяет, какой сайт отдать.

**4. Почему в diagnose проверка DNS идёт первой и почему функция останавливается на первой ошибке?**
Для TCP-соединения нужен IP-адрес, а получить его можно только через DNS. Каждый
следующий шаг имеет смысл, только если прошёл предыдущий: без IP нельзя проверить
TCP, без TCP-соединения — HTTP. Остановка на первой ошибке точно указывает уровень,
на котором возникла проблема.

**5. Почему результат ping может отличаться от результата TCP-проверки?**
ping использует протокол ICMP (межсетевой уровень), а TCP-проверка — TCP-соединение
с конкретным портом (транспортный уровень). Файрвол может блокировать ICMP, но
пропускать TCP 80/443 (ping не проходит, сайт работает), или наоборот — узел
отвечает на ping, но нужный порт закрыт. Также ping может быть запрещён обычному
пользователю.

**6. Зачем в VLSM блоки выделяются от большего к меньшему?**
Чтобы каждый блок начинался с адреса, кратного его размеру, и блоки шли подряд без
пропусков и наложений, экономно расходуя адресное пространство.

**7. Почему в формуле 2^h − 2 вычитаются два адреса?**
Адрес сети (все биты узла = 0) и широковещательный адрес (все биты узла = 1) не
назначаются узлам.

**8. Какие утилиты соответствуют проверкам программы?**

| Проверка программы | Утилита |
|---|---|
| check_dns | `nslookup`, `dig`, `host` |
| check_tcp | `telnet хост порт`, `nc -zv хост порт`, `Test-NetConnection -Port` |
| check_http | `curl -I`, `wget`, браузер |
| check_ping | `ping` |
| vlsm | ручной расчёт / IP-калькулятор (`ipcalc`) |

## Общий вывод

Программа `diag.py` автоматизирует диагностику сети и проверяет несколько уровней
стека TCP/IP:

- **прикладной уровень** — DNS (check_dns, заменяет nslookup) и HTTP (check_http,
  заменяет curl);
- **транспортный уровень** — установку TCP-соединения с портом и время соединения
  (check_tcp, заменяет telnet / Test-NetConnection), с различением отказа,
  таймаута и отсутствия маршрута;
- **межсетевой уровень** — доступность узла по ICMP (check_ping, вызывает ping)
  и IP-адресацию (vlsm — расчёт подсетей).

Функция diagnose выполняет проверки по порядку и останавливается на первой ошибке,
сразу называя уровень, на котором возникла проблема. Расчёт VLSM для сети
192.168.1.0/24 выполнен программой, прошёл самопроверку и совпадает с ручным расчётом.
